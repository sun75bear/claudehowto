# 1. なぜ Claude Code なのか

!!! abstract "このページでできるようになること"
    チャット型 AI と Claude Code の違いが、具体的な作業のイメージとして分かります。**このサイトでいちばん大事なページ**です。

## チャット型 AI の天井

「ファイルを添付 → 頼む → 返事をコピー → 元のファイルに貼る → 次のファイルへ」。この流れに覚えがあるはずです。

3つならまだ我慢できます。**30個あったらどうでしょうか。**

この「**1往復につき1ファイル、反映は手作業**」という構造が、チャット型 AI の天井です。しかもこの天井は ChatGPT でも Gemini でも Claude のチャットでも同じで、**どこの会社のものを使っても変わりません。**

## Claude Code が壊すもの

渡すのはファイルではなく**フォルダ**です。そして Claude Code は、**探す**（何があるか調べる）・**読む**・**書く**（コピペは発生しない）・**実行する**（結果を確認する）・**直す**（おかしければ自分で気づく）を自分でやります。

つまり、**あなたが手を動かしていた部分を引き取ります。**

## 具体例1: 30個の議事録から宿題を拾い出す（コードを書かない仕事）

半年分の議事録が入ったフォルダから、「やると言ったまま終わっていないこと」を洗い出したい、という場面です。

=== "チャットでやると"

    ```mermaid
    sequenceDiagram
        actor You as あなた
        participant Chat as チャット
        loop 議事録の数だけ（30回）
            You->>Chat: 1つ開いてコピーして貼る
            Chat-->>You: 抜き出した結果
            You->>You: メモ帳に貼って保存
        end
        You->>You: 30個分を突き合わせて整理
    ```

    **所要: 1〜2時間。しかも途中で飽きる。**

=== "Claude Code だと"

    フォルダを選んで、1回こう頼むだけです。

    ```text
    このフォルダの議事録を全部読んで、アクションアイテムを洗い出してください。

    - 誰が・何を・いつまでに、の形式で一覧表にする
    - 後の回の議事録で「完了」と報告されているものは除く
    - 期限が過ぎているものには印を付ける
    - 担当者が書かれていないものは「担当未定」と明記する
    ```

    ```mermaid
    sequenceDiagram
        actor You as あなた
        participant CC as Claude Code
        You->>CC: フォルダと条件を1回伝える
        CC->>CC: 30個を探して読む
        CC->>CC: 突き合わせて重複を除く
        CC-->>You: 一覧表
    ```

    **所要: 数分。** 読むのも突き合わせるのも Claude Code の仕事になります。

差は「速い」ではなく **「やる気になるかどうか」** です。1〜2時間かかる作業は後回しにされ、永遠に着手されません。

## 具体例2: バグの原因を追う（コードを書く人向け）

=== "チャットでやると"

    1. エラーメッセージを貼る
    2. 「このファイルを見せて」と言われる
    3. 該当ファイルを開いて貼る
    4. 「呼び出し元も見たい」と言われる
    5. 探して貼る
    6. **原因にたどり着くまで、これが続く**
    7. 修正案をコピーして、自分でファイルに反映する
    8. 実行して確認する。まだ直っていない。1に戻る

=== "Claude Code だと"

    ```text
    このエラーが出ています。原因を調べて直してください。
    直したらテストを実行して、通ることを確認してください。

    〈エラーメッセージを貼る〉
    ```

    関連ファイルを**自分で探して読み**、修正して、**テストを実行して**、失敗すればまた直します。あなたは結果を確認するだけです。

## 「自走する」ということ

両方の例に共通するのは、**一度の指示で複数の手順を自分で進める**という点です。これを「エージェント型」と呼びます。

裏返せば **勝手にファイルを書き換えられる**ということでもあるので、Claude Code には変更前に確認を取る**承認の仕組み**があります。この使いこなしが実務では一番大事なので、[4. 最初のセッション](04-first-session.md) で丁寧に扱います。

!!! tip "最初は「変更させない」モードから"
    方針だけ提案させて、ファイルには触らせない **Plan モード**があります。慣れるまではこれで感覚をつかむのが安全です。

## どこで使えるか

デスクトップアプリ、ターミナル、エディタ拡張、Web、モバイル——**同じ中身が複数の入口から使えます。** 設定（後述する `CLAUDE.md` など）はどの入口でも共有されるので、あとから乗り換えても無駄になりません。**このサイトはデスクトップアプリで進めます**（選び方は [3. インストールする](03-setup.md)）。

!!! note "2026年8月時点の情報です"
    最新は [Claude Code 公式ドキュメント](https://code.claude.com/docs/en/overview) を確認してください。

## まとめ

- チャットの天井は「**1往復1ファイル、反映は手作業**」。これは各社共通
- Claude Code は**探す・読む・書く・実行する・直す**を引き取る
- 効くのは「**複数ファイルにまたがる、手数の多い作業**」。コードに限らない
- 自走するからこそ、**承認の仕組み**を理解して使う
