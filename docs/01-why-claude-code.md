# 1. なぜ Claude Code なのか

!!! abstract "このページでできるようになること"
    チャット型 AI と Claude Code の違いが、具体的な作業のイメージとして分かります。**このサイトでいちばん大事なページ**です。

## チャット型 AI の天井

チャットで仕事をしたことがある方なら、この流れに覚えがあるはずです。

1. ファイルを1つ添付する
2. 「要約して」と頼む
3. 返ってきた文章をコピーする
4. 元のファイルを開いて貼り付ける
5. **次のファイルで、1に戻る**

ファイルが3つならまだ我慢できます。**30個あったらどうでしょうか。**

この「1往復につき1ファイル、反映は手作業」という構造が、チャット型 AI の天井です。そしてこの天井は、ChatGPT でも Gemini でも Claude のチャットでも同じです。**どこの会社のものを使っても変わりません。**

## Claude Code が壊すもの

Claude Code に渡すのは、ファイルではなく**フォルダ**です。そして Claude Code は次のことを自分でやります。

- **探す** — フォルダの中に何があるか自分で調べる
- **読む** — 必要なファイルを自分で開いて読む
- **書く** — ファイルを直接書き換える。コピペは発生しない
- **実行する** — コマンドやスクリプトを実行して、結果を確認する
- **直す** — 結果がおかしければ、自分で気づいて直す

つまり、**あなたが手を動かしていた部分を引き取ります。**

## 具体例1: 30個の議事録から宿題を拾い出す（コードを書かない仕事）

半年分の議事録が入ったフォルダから、「やると言ったまま終わっていないこと」を洗い出したい、という場面です。

=== "チャットでやると"

    1. 議事録を1つ開いて、内容をコピーして貼る
    2. 「未完了のアクションアイテムを抜き出して」と頼む
    3. 結果をメモ帳にコピーする
    4. **これを30回繰り返す**
    5. 30個分のメモを自分で突き合わせて、あとで完了したものを消す

    **所要: 1〜2時間。しかも途中で飽きる。**

=== "Claude Code だと"

    フォルダを選んで、1回こう頼むだけです。

    ```text
    このフォルダの議事録を全部読んで、アクションアイテムを洗い出してください。

    - 誰が・何を・いつまでに、の形式で一覧表にする
    - 後の回の議事録で「完了」と報告されているものは除く
    - 期限が過ぎているものには印を付ける
    - 担当者が書かれていないものは「担当未定」と明記する
    ```

    あとは待つだけです。**30個読むのも、突き合わせるのも、Claude Code の仕事**になります。

    **所要: 数分。**

差は「速い」ではなく、**「やる気になるかどうか」**です。1〜2時間かかる作業は、たいてい後回しにされて永遠に着手されません。

## 具体例2: バグの原因を追う（コードを書く人向け）

=== "チャットでやると"

    1. エラーメッセージを貼る
    2. 「このファイルを見せて」と言われる
    3. 該当ファイルを開いて貼る
    4. 「呼び出し元も見たい」と言われる
    5. 探して貼る
    6. **原因にたどり着くまで、これが続く**
    7. 修正案をコピーして、自分でファイルに反映する
    8. 実行して確認する。まだ直っていない。1に戻る

=== "Claude Code だと"

    ```text
    このエラーが出ています。原因を調べて直してください。
    直したらテストを実行して、通ることを確認してください。

    〈エラーメッセージを貼る〉
    ```

    関連ファイルを**自分で探して読み**、修正して、**テストを実行して**、失敗すればまた直します。あなたは結果を確認するだけです。

## 「自走する」ということ

ここまでの例に共通するのは、**一度の指示で複数の手順を自分で進める**という点です。これを「エージェント型」と呼びます。

便利ですが、裏返すと **勝手にファイルを書き換えられる**ということでもあります。だから Claude Code には**承認の仕組み**があり、変更前に「これをやっていいか」を確認してきます。

この確認の使いこなしが実務では一番大事なので、[4. 最初のセッション](04-first-session.md) で丁寧に扱います。

!!! tip "最初は「変更させない」モードから"
    方針だけ提案させて、ファイルには触らせない **Plan モード**があります。慣れるまではこれで感覚をつかむのが安全です。

## どこで使えるか

Claude Code は同じ中身が複数の入口から使えます。

| 入口 | 向いている人 |
|---|---|
| **デスクトップアプリ** | **全員。ターミナル不要。このサイトはこれで進めます** |
| ターミナル（CLI） | コマンド操作に慣れている人 |
| VS Code / JetBrains 拡張 | 普段からそのエディタで作業する人 |
| Web（`claude.ai/code`） | 手元に環境を作らず試したい人 |
| モバイルアプリ | 外出先で長時間かかる作業を仕掛けておきたい人 |

設定（後述する `CLAUDE.md` など）はどの入口でも共有されるので、あとから乗り換えても無駄になりません。

!!! note "2026年8月時点の情報です"
    最新は [Claude Code 公式ドキュメント](https://code.claude.com/docs/en/overview) を確認してください。

## まとめ

- チャットの天井は「**1往復1ファイル、反映は手作業**」。これは各社共通
- Claude Code は**探す・読む・書く・実行する・直す**を引き取る
- 効くのは「**複数ファイルにまたがる、手数の多い作業**」。コードに限らない
- 自走するからこそ、**承認の仕組み**を理解して使う
